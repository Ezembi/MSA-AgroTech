### <a name="_qmphm5d6rvi3"></a>**Решение**
**Для Backend** была выбрана связка Java(Kotlin) + Spring.

**Плюсы:**
- Зрелая экосистема: Spring Boot закрывает типовые задачи (web, security, data, messaging) “из коробки”. 
- Производительность и масштабирование: JVM хорошо держит нагрузку, есть тюнинг, профилирование, стабильный GC.
- Надёжность в проде: инструменты и практики enterprise-уровня, предсказуемое поведение, долгий жизненный цикл.
- Отличная интеграция с инфраструктурой: SQL/NoSQL, Kafka/RabbitMQ, observability (Micrometer, OpenTelemetry), облака.
- Быстрая разработка: авто-конфигурация, стартеры, Spring Data, миграции, тестирование.
- Kotlin как бонус: меньше бойлерплейта, null-safety, корутины (удобно для IO), при этом вся Java-экосистема доступна.

**Минусы:**
- Тяжеловесность: Spring (особенно “всё подряд”) увеличивает размер приложения, время старта и потребление памяти.
- Память: по сравнению с Go/Node часто выше базовый расход RAM.
- Необходимо следить за версиями Spring/Boot, зависимостей, уязвимости (нужно регулярно патчить).

**Для хранения файлов** (фото/видео) было выбрано S3 хранилище, т.к. это оптимальный вариант для хранения неструкткрированных данных.

**Для хранения данных** был выбран PostgreSQL 

**Плюсы:**
- Надёжность и ACID: корректные транзакции и предсказуемость данных. 
- Богатые возможности SQL: сложные запросы, оконные функции, CTE, аналитика. 
- Расширяемость: типы данных (JSONB, массивы, гео), расширения (PostGIS и др.). 
- Производительность: хорошие индексы, планировщик запросов, параллелизм. 
- Удобная эксплуатация: репликация, бэкапы, роли/права, зрелые инструменты. 
- Open-source и популярность: большая экосистема, проще найти поддержку и специалистов.

**Минусы:**
- Миграции схемы: изменения таблиц на больших объёмах (ALTER, индексы) могут быть долгими и требуют аккуратного планирования.
- Запись и конкуренция: при высокой write-нагрузке возможны блокировки/конфликты, нужен аккуратный дизайн транзакций и индексов. 
- Эксплуатационная сложность: бэкапы/восстановление, репликация, вакуум (autovacuum), тюнинг — требует опыта.

**Для построения отчётов** был выбран СlickHouse, т.к. он отлично справляется с построением отчётов (выборки) по сотням тысяч записей.

**Для Web приложения** был выбран TypeScript и Python из-за большого выбора фреймворков с готовыми компонентами для построения отчётов.

**Для мобильных приложений** выбраны Flutter, т.к. он позволяет создавать приложение сразу под две самые популярные мобильные платформы.

**Для очереди сообщений** выбрана Apache Kafka, т.к. это высокопроизводительный брокер сообщений.
